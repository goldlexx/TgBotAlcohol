# Отдельный закрытый тестовый контур

Этот порядок применяется после разрешения владельца на облачный тест и получения отдельного тестового бота. Для облачного теста используй разрешённые тестовые чаты и синтетические значения. Локальная проверка 200 профилей использует имитацию Telegram.

## Cloudflare Workers Free

Рабочие имена — Worker `tgbot-alcohol`, D1 `tgbot-alcohol-test`. Локальный `wrangler.jsonc` содержит нулевой ID базы и выключает `workers.dev` и URL предварительного просмотра. Рабочие имена проверены в подключённом аккаунте 24 ноября 2026 года. Найдено 6 Workers, 5 D1 и 2 Cron, в том числе 3 D1 с именами TgBotSmoke и 1 Cron у TgBotSmoke. OAuth Wrangler не дал доступ к сведениям о подписке, поэтому фактический тариф нужно сверить в панели перед облачным тестом.

Для Free документированы 100 000 Workers-запросов в день, 10 мс CPU на HTTP или Cron, до 50 подзапросов, до 5 Cron в аккаунте и 50 запросов D1 на вызов Worker. D1 Free предоставляет 5 млн прочитанных и 100 тыс. записанных строк в день, 500 МБ на базу и 5 ГБ на аккаунт. Квоты разделяются с имеющимися ресурсами. Перед облачным тестом сверь тариф, доступный слот Cron и запас квот. При нехватке ресурса останови развёртывание. [Workers Limits](https://developers.cloudflare.com/workers/platform/limits/), [D1 Limits](https://developers.cloudflare.com/d1/platform/limits/), [D1 Pricing](https://developers.cloudflare.com/d1/platform/pricing/).

Cron выбирает до 8 строк задания через индекс `due_jobs`. Для каждой строки до пяти обращений к D1 и одна отправка в Telegram. Ещё одно обращение выбирает задания и одно выполняет почасовую очистку. Такой расчёт ограничивает число подзапросов, а обработка всего батча в 10 мс зависит от облачных измерений. Метрики CPU, задержку, число прочитанных и записанных строк проверяй отдельно по Worker и D1. Снимай метрики без тел сообщений и секретов.

## BotFather и Cloudflare

1. В BotFather создай отдельного тестового бота через `/newbot`, согласуй username и запрети добавление в группы. Имя — «Счастье без алкоголя». Сохрани токен в менеджере секретов. Описание — «Дни без алкоголя, личный прогресс и идеи для жизни без спиртного. Бесплатно, без рекламы». Команды — `start`, `help`, `privacy`, `delete`.
2. Из финального коммита скопируй `wrangler.jsonc` в игнорируемый `wrangler.test.local.jsonc`. Создай D1 командой `npx.cmd wrangler d1 create tgbot-alcohol-test` и вставь выданный ID. В первой версии установи пустой список Cron и оставь `workers_dev: false`. Примени миграции командой `npx.cmd wrangler d1 migrations apply DB --remote --config wrangler.test.local.jsonc`. Разверни эту версию с тем же `--config`.
3. Командой `npx.cmd wrangler secret put ИМЯ --config wrangler.test.local.jsonc` введи `TELEGRAM_TOKEN`, уникальный случайный `WEBHOOK_SECRET` из символов A–Z, a–z, 0–9, `_`, `-`, и `ALLOWED_CHAT_IDS` с ID разрешённых тестовых личных чатов через запятую. Сверь, что Worker показывает только необходимые привязки. Включи тестовый `workers.dev`, верни `* * * * *` и повтори deploy из того же коммита.
4. Через Bot API `getMe` сверь username с созданным тестовым ботом. С помощью `getWebhookInfo` убедись, что у нового бота ещё нет webhook. Для него вызови `setWebhook` с HTTPS URL `/telegram/webhook`, ранее заданным `secret_token` и `allowed_updates` со значениями `message` и `callback_query`. Сверь webhook и проверь один синтетический сценарий вручную в разрешённом чате. Токен и URL Bot API с токеном храни вне репозитория, журналов и отчётов. [Telegram Bot API](https://core.telegram.org/bots/api#setwebhook).
5. После теста сними webhook отдельного тестового бота, останови Cron, удали тестовые данные согласно [политике тестового контура](../DECISIONS.md). Для повторной проверки подготовь пустую тестовую D1 с синтетическими фикстурами.

До пилота с реальными данными нужны утверждённые оператор, политика и сроки хранения, клиническая редакция и правовая оценка применимых требований, включая 152-ФЗ, возможную локализацию и трансграничную обработку. Итоговое решение о публичном запуске принимает владелец.
